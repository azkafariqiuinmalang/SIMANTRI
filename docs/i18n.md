# Bahasa Indonesia / Basa Jawa

## Scope and editorial style

- Indonesian (`id`) remains the default and fallback. Javanese (`jv`) uses Latin-script krama alus, with clear, short agricultural instructions.
- Keep SIMANTRI, SIMA, proper names, scientific disease names, chemical names, doses, percentages, and units unchanged. Do not infer or translate arbitrary user content or retrieved documents.
- Main UI coverage: landing, login/registration labels, dashboard shell, dashboard, SIMA, price prediction, disease detection, profile, and knowledge suggestions.
- The existing Dunia Brambang exhibition, legal documents, and specialized administrator/reviewer pages retain their original content. Shared navigation is bilingual. They are not automatically machine-translated.
- A fluent Javanese speaker should review the copy before a public release; automated tests validate coverage and behavior, not linguistic quality.

## Architecture

`src/lib/locales/jv.json` maps exact Indonesian UI messages to Javanese. The Indonesian source text is the fallback; no translation service is called. `translate(source, language, params)` supports named parameters such as `{days}` without altering supplied values.

`LanguageProvider` supplies `language`, `setLanguage`, and `t`. It uses a hydration-safe Indonesian server snapshot, stores preference in `localStorage` under `simantri.language`, synchronizes other tabs, and sets the document's BCP 47 `lang` attribute. If storage is unavailable, preference lasts for the current page session. Language changes do not reset forms or chat history.

The native `LanguageSwitcher` works with keyboard and touch. It is available in the dashboard header and as a small persistent control on public pages.

## SIMA

Both chat clients send an optional `language: 'id' | 'jv'` with the existing payload. Missing or unknown values behave exactly as Indonesian. This is an additive, backward-compatible request option; response fields are unchanged.

The chat route appends only a fixed, allowlisted language instruction. Retrieval still uses the original question, and validation, injection detection, output sanitization, model selection, and database writes are unchanged. Suggested-question translations are for display; their original query is retained for retrieval and conversation payloads. Existing messages and quoted sources are not retranslated when the language changes.

Javanese fallback guidance is available when generation is unavailable; a retrieved excerpt stays in its original language and is explicitly identified as such. Security refusal messages retain the existing guardrail wording. Live model output can vary and still requires review.

## Validation

Run `node --test tests/i18n.test.cjs`, `npx tsc --noEmit`, `npm run lint`, and `npm run build`.

Tests use the installed TypeScript compiler in memory and stub external services; they do not send requests to Supabase or Gemini. They check defaults, dictionary coverage, unknown-content preservation, placeholders, allowlisted instructions, and retrieval/response compatibility.
